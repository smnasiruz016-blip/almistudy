### Spec command pattern (proven 5+ times today)

- **Self-contained code-block format** — Nasir pastes verbatim to CC, no manual stitching
- **Pre-flight verification** — grep existing entries by domain + name, identify promotion candidates, confirm region/path conventions, report before writing
- **Inline data spec** — no file refs, all fields per entry
- **Shared fields once + per-entry override** — accreditation blocks shared, per-entry studentNotes/tuitionNote
- **Gates** — typecheck/lint/build/banned-verb-audit/niche-framing-verification/city-tally
- **PR commit message** — structured bullets per-PR with what changed
- **"Don't merge — Nasir's call"** — every command ends this way
- **Hard-ban verbs** zero tolerance: discover/unlock/dream/transform/empower/journey/aspire/limitless/"limited time"/"last chance"
- **Soft-flag verbs** context-check: start/now/today/build (e.g., "Australia is **now** top global study destination per QS 2025" is factual, not promotional → keep)
- **Split as PART 1 of N / PART 2 of N for long specs** — proven essential, truncation hit 3+ times today before splitting
- **Request PR URL explicitly in CC's report** — CC sometimes omits if not asked

### Merge conflict pattern (hit twice today)

Both India PR #8 and Pakistan PR #6 hit merge conflicts in `lib/universities-publishable.json` after other PRs merged. CC's resolution workflow:
1. `git fetch origin`
2. `git checkout <branch>`
3. `git rebase origin/main`
4. Resolve conflict (non-overlapping entries — keep both sets)
5. Run all gates locally before force-push
6. `git push --force-with-lease` (not `--force`)

Both resolved cleanly using this pattern. **For future sessions:** open and merge each PR sequentially when they touch the same file; do not stack multiple unmerged PRs against the same file or conflicts compound.
