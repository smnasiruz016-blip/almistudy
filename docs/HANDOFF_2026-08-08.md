## THE EGYPT MISS — worth reading before the next pass

Tonight's per-batch tag fix used a fixed word list (`Region|Province|County|State|District|Division`)
and **missed `Governorate`**, so 20 Egypt rows shipped to production with
"Region: Cairo Governorate Governorate". Caught afterwards and fixed by `_fix_region_tags.py`, which
collapses **any** repeated word run instead of a named list — the right shape.

**Correction on severity.** Earlier commit messages today (`752d50a`, `fd9d1c6`) called the doubled
tags "user-visible text". They are not. Verified against production: `Region: …` tags render nowhere —
`grep 'Region:'` and `grep 'Governorate'` both return 0 on a live university page, and `categoryTags`
appears in `lib/page-relations.ts` only as a field on the `University` type, with no page printing it.
So this was **latent data hygiene, not a visible defect**: worth fixing so the strings are correct
wherever they are eventually used, but it never reached a reader. Treat it as low priority if it
recurs, not as a production text bug.

That script is also correctly **scoped to tags starting `Region: `**, and that scoping is load-bearing:
three tags elsewhere contain legitimate repeated words — `Vanity-marketing phone (7799 7799)`,
`Dr. Hassan Hassan founded`, and `Federal public public-health degree-awarding institute.` A
dataset-wide collapse would have corrupted all three.
